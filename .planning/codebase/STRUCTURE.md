## Directory Purposes

**`src/main/grammars/`**
- Purpose: Lexer and parser grammar definitions
- Contains: JFlex and BNF source files (hand-edited)
- Key files: `MakoLexer.flex` (tokenization), `Mako.bnf` (parsing rules)
- Note: Sources are committed; generated files go to `src/main/gen/`

**`src/main/gen/`**
- Purpose: Generated lexer, parser, and PSI code (committed to git)
- Contains: _MakoLexer.java (from JFlex), MakoParser.java + MakoTypes.java + Mako*Impl.java (from GrammarKit)
- Generated by: `./gradlew generateMakoLexer` (JFlex) and Tools > Generate Parser Code (GrammarKit IDE action)
- Note: Must be manually regenerated after grammar changes; purgeOldFiles=false to avoid deleting non-lexer files

**`src/main/kotlin/com/github/kimuth/jetbrainsmakotemplateplugin/`**
- Purpose: Root package for plugin code
- Contains: MakoLanguage, MakoFileType, MakoIcons definitions

**`src/main/kotlin/.../lang/`**
- Purpose: Core language support (parsing, tokens, PSI)
- Contains: MakoParserDefinition, MakoLexerAdapter, token/element type definitions, PSI root node
- Key responsibility: Bridge between JetBrains platform and Mako language

**`src/main/kotlin/.../lang/psi/`**
- Purpose: Program Structure Interface (PSI) root and mixins
- Contains: `MakoFile.kt` (root PSI element), mixin implementations for named elements
- Pattern: Mixins extend generated PSI implementations (wired via Mako.bnf `mixin` attribute)

**`src/main/kotlin/.../lang/highlighting/`**
- Purpose: Syntax highlighting and bracket matching
- Contains: Token-to-color mapping, color settings page, paired brace matcher
- Used by: Editor when rendering file; users customize colors in Settings > Editor > Color Scheme

**`src/main/kotlin/.../lang/folding/`**
- Purpose: Code folding regions (collapsible blocks)
- Contains: MakoFoldingBuilder scans PSI tree, returns foldable regions
- Folds: def/block tags (expanded by default), doc comments (collapsed), module blocks (collapsed), control flow (for/if/while)

**`src/main/kotlin/.../lang/editing/`**
- Purpose: Text editing aids (comment/uncomment)
- Contains: MakoCommenter defines line (##) and block (<%doc>) comment syntax
- Used by: Ctrl+/ action to toggle comments

**`src/main/kotlin/.../lang/structure/`**
- Purpose: Structure view (file outline)
- Contains: MakoStructureViewFactory (entry point), MakoStructureViewModel (filters defs/blocks), MakoStructureViewElement (tree presentation)
- Shows: Def and block tags in a tree; nested defs/blocks visible; expression/code blocks hidden

**`src/main/resources/META-INF/`**
- Purpose: Plugin manifest and theme definitions
- Contains: `plugin.xml` (extension point registrations), color scheme XMLs (theme colors)
- Key: `plugin.xml` declares fileType, parser, highlighter, folder, structure view, commenter, bracket matcher

**`src/main/resources/colorSchemes/`**
- Purpose: Editor color scheme definitions (light and dark)
- Contains: MakoDefault.xml (light theme), MakoDarcula.xml (dark theme)
- Maps: Token types to RGB colors for editor rendering

**`src/test/kotlin/`**
- Purpose: Test source code
- Contains: MakoParsingTest (fixture-based), MakoLexerTest (unit), MakoFoldingTest, MakoStructureViewTest
- Pattern: Test class name maps to testData file pairs (MyTest.kt → MyTest.mako + MyTest.txt)

**`src/test/testData/parser/`**
- Purpose: Parser fixture test data
- Contains: `.mako` input files and `.txt` expected PSI tree outputs
- Pattern: Create `.mako` input, run test to auto-generate `.txt`, verify and commit
- Example: `WellFormedFile.mako` (input) + `WellFormedFile.txt` (expected tree)

## Key File Locations

**Entry Points:**
- `src/main/resources/META-INF/plugin.xml`: Extension point registrations; platform reads this to load plugin
- `src/main/kotlin/.../MakoLanguage.kt`: Language singleton; must match `language` attribute in plugin.xml

**Configuration:**
- `build.gradle.kts`: Plugin ID, version, dependencies, build tasks
- `src/main/resources/META-INF/plugin.xml`: Extension declarations (fileType, parser, highlighter, etc.)
- `.env` files: Not present; no secrets management (plugin configs hardcoded in plugin.xml)

**Core Logic:**
- `src/main/grammars/MakoLexer.flex`: Tokenization rules; tracks brace depth for nested `${...}` expressions
- `src/main/grammars/Mako.bnf`: Parsing rules; defines structure of all Mako constructs (tags, expressions, code blocks)
- `src/main/kotlin/.../lang/MakoParserDefinition.kt`: Lexer/parser factory; registered extension point
- `src/main/kotlin/.../lang/MakoLexerAdapter.kt`: State encoding for incremental re-lexing; encodes brace depth in state integer

**Testing:**
- `src/test/kotlin/.../MakoParsingTest.kt`: Parser tests using fixture comparison (doTest compares PSI tree to .txt file)
- `src/test/kotlin/.../MakoLexerTest.kt`: Lexer unit tests (token stream validation)
- `src/test/testData/parser/`: Fixture pairs (.mako inputs + .txt expected trees)

## Naming Conventions

**Files:**
- `Mako*.kt`: Plugin classes (MakoLanguage.kt, MakoFileType.kt, etc.)
- `MakoParsingTest.kt`: Test class (maps to testData parser/*.mako)
- `*.flex`: JFlex grammar file (MakoLexer.flex)
- `*.bnf`: GrammarKit BNF grammar (Mako.bnf)

**Directories:**
- `lang/`: Core language support (parsing, PSI, tokens)
- `lang/highlighting/`: Syntax highlighting and bracket matching
- `lang/folding/`: Code folding
- `lang/editing/`: Text editing aids
- `lang/structure/`: Structure view (outline)
- `lang/psi/`: PSI tree and mixins
- `gen/`: Generated code (lexer, parser, PSI)
- `grammars/`: Grammar source files
- `testData/parser/`: Parser test fixtures

**Packages:**
- Root: `com.github.kimuth.jetbrainsmakotemplateplugin`
- Language support: `...lang`
- Generated PSI: `...lang.psi`, `...lang.psi.impl`
- Generated parser: `...lang.parser`

**Tokens:**
- `EXPR_START`, `EXPR_END`, `EXPR_CONTENT`: Expression tokens
- `TAG_OPEN_DEF`, `TAG_OPEN_BLOCK`, `TAG_OPEN_INHERIT`, `TAG_OPEN_INCLUDE`, `TAG_OPEN_NAMESPACE`, `TAG_OPEN_PAGE`: Tag openers
- `TAG_CLOSE`, `END_TAG`: Tag closers
- `CONTROL_LINE`: Control line (%, %for, %if, etc.)
- `CODE_OPEN`, `CODE_CONTENT`, `CODE_CLOSE`: Code block
- `MODULE_OPEN`, `MODULE_CONTENT`, `CODE_CLOSE`: Module-level code (<%! %>)
- `LINE_COMMENT`: Line comment (##)
- `DOC_OPEN`, `DOC_CONTENT`, `DOC_CLOSE`: Doc comment (<%doc>)
- `TEMPLATE_TEXT`: Plain template content (HTML, etc.)

**PSI Elements (generated):**
- `MakoFile`: Root PSI node
- `MakoDefTag`, `MakoBlockTag`: Named container tags (implement PsiNamedElement)
- `MakoInheritTag`, `MakoIncludeTag`, `MakoNamespaceTag`, `MakoPageTag`: Single-construct tags
- `MakoExpression`: `${...}` expression
- `MakoControlLineStmt`: Control line (%, %for, %if, etc.)
- `MakoCodeBlock`: Code block (<% %>)
- `MakoModuleBlock`: Module-level code (<%! %>)
- `MakoDocComment`: Doc comment (<%doc>)
- `MakoLineCommentRule`: Line comment (##)
- `MakoTemplateTextContent`: Plain text

## Where to Add New Code

**New Feature (e.g., code completion, rename refactoring):**
- Primary code: Create new file in appropriate subdirectory under `src/main/kotlin/.../lang/`
  - If syntax-related: `lang/highlighting/`
  - If navigation-related: `lang/structure/`
  - If editing-related: `lang/editing/`
  - If it's a core feature: directly under `lang/`
- Tests: `src/test/kotlin/.../lang/MyFeatureTest.kt`
- Registration: Add extension point in `src/main/resources/META-INF/plugin.xml`

**New Component/Module (e.g., inspections, quick fixes):**
- Implementation: Create package under `lang/` with component class and supporting classes
  - Example: `lang/inspections/` for inspection classes
  - Example: `lang/quickfixes/` for quick fix classes
- Tests: Mirror package under `src/test/kotlin/`
- Registration: Add extension point(s) in `plugin.xml`

**Utilities/Helpers (e.g., PSI traversal, text manipulation):**
- Shared helpers: `src/main/kotlin/.../lang/util/` (create if missing)
  - Keeps utilities separate from feature builders
  - Makes reuse across features easy
- Tests: `src/test/kotlin/.../lang/util/UtilNameTest.kt`

**Parser/Lexer Changes:**
- Lexer rules: Edit `src/main/grammars/MakoLexer.flex`
- Parser rules: Edit `src/main/grammars/Mako.bnf`
- After edit:
  - Lexer: Run `./gradlew generateMakoLexer` → regenerates `src/main/gen/.../._MakoLexer.java`
  - Parser: Use IDE action "Tools > Generate Parser Code" → regenerates parser + PSI in `src/main/gen/`
- Commit: Generated files are committed; do not modify by hand

**Test Fixtures (parser):**
- Input file: `src/test/testData/parser/MyTest.mako` (create, add test case)
- Test code: `src/test/kotlin/.../lang/MakoParsingTest.kt` add test method `fun testMyTest() = doTest(true)`
- Expected output: Run test once; `MakoParsingTest.doTest()` generates `MyTest.txt`
- Verification: Review generated `.txt` file; verify PSI tree is correct; commit both files

## Special Directories

**`src/main/gen/`**
- Purpose: Generated code (auto-generated, committed to git)
- Generated: Yes (by `./gradlew generateMakoLexer` and GrammarKit IDE action)
- Committed: Yes (important for reproducible builds)
- Editing: Never edit by hand; regenerate from grammars if changes needed

**`.idea/`**
- Purpose: IntelliJ IDE project configuration
- Generated: Yes (created by IDE on first open)
- Committed: Partially (often in .gitignore; some teams commit it)
- Note: Not required for builds; developers generate locally

**`.gradle/`**
- Purpose: Gradle cache (dependencies, build outputs)
- Generated: Yes (created by Gradle)
- Committed: No (in .gitignore)
- Note: Safe to delete; Gradle regenerates on next build
