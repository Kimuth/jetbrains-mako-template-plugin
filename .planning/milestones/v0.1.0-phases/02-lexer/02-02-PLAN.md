**Step 2: Create `MakoParserDefinition.kt`:**

```kotlin
package com.github.kimuth.jetbrainsmakotemplateplugin.lang

import com.github.kimuth.jetbrainsmakotemplateplugin.MakoLanguage
import com.github.kimuth.jetbrainsmakotemplateplugin.lang.psi.MakoFile
import com.intellij.lang.ASTNode
import com.intellij.lang.ParserDefinition
import com.intellij.lang.PsiParser
import com.intellij.lexer.Lexer
import com.intellij.openapi.project.Project
import com.intellij.psi.FileViewProvider
import com.intellij.psi.PsiElement
import com.intellij.psi.PsiFile
import com.intellij.psi.tree.IFileElementType
import com.intellij.psi.tree.TokenSet

class MakoParserDefinition : ParserDefinition {
    companion object {
        val FILE = IFileElementType(MakoLanguage)
    }

    override fun createLexer(project: Project): Lexer = MakoLexerAdapter()

    override fun getWhitespaceTokens(): TokenSet = MakoTokenSets.WHITESPACE

    override fun getCommentTokens(): TokenSet = MakoTokenSets.COMMENTS

    override fun getStringLiteralElements(): TokenSet = TokenSet.EMPTY

    override fun createParser(project: Project): PsiParser =
        throw UnsupportedOperationException("MakoParser not yet implemented - Phase 3")

    override fun getFileNodeType(): IFileElementType = FILE

    override fun createFile(viewProvider: FileViewProvider): PsiFile = MakoFile(viewProvider)

    override fun createElement(node: ASTNode): PsiElement =
        throw UnsupportedOperationException("MakoElement factory not yet implemented - Phase 3")
}
```

Key wiring points:
- `createLexer()` returns `MakoLexerAdapter()` — this is the link to Plan 01's lexer
- `getWhitespaceTokens()` uses `MakoTokenSets.WHITESPACE` — platform skips these in PSI tree
- `getCommentTokens()` uses `MakoTokenSets.COMMENTS` — platform marks these as comments
- `createParser()` throws — Phase 3 replaces this with GrammarKit-generated parser
- `createElement()` throws — Phase 3 replaces this with PSI element factory
- `createFile()` returns `MakoFile(viewProvider)` — gives the platform a PsiFile root node

**Step 3: Register in `plugin.xml`:**

Add inside the `<extensions defaultExtensionNs="com.intellij">` block, after the existing `<fileType>` element:

```xml
<lang.parserDefinition language="Mako Template"
    implementationClass="com.github.kimuth.jetbrainsmakotemplateplugin.lang.MakoParserDefinition"/>
```

The `language="Mako Template"` MUST match the Language ID exactly (same string used in MakoLanguage constructor and MakoFileType getName()). This is the string identity contract established in Phase 1.

**Create `src/test/kotlin/com/github/kimuth/jetbrainsmakotemplateplugin/lang/MakoLexerTest.kt`:**

Use IntelliJ's `BasePlatformTestCase` or a plain test approach — instantiate `MakoLexerAdapter`, call `start(text)`, and iterate through tokens comparing against expected types.

Write a helper method:
```kotlin
private fun tokenize(text: String): List<Pair<IElementType, String>> {
    val lexer = MakoLexerAdapter()
    lexer.start(text)
    val tokens = mutableListOf<Pair<IElementType, String>>()
    while (lexer.tokenType != null) {
        tokens.add(lexer.tokenType!! to lexer.tokenText)
        lexer.advance()
    }
    return tokens
}
```

Write test methods verifying:

1. **Template text:** `"<html>Hello</html>"` -> all `TEMPLATE_TEXT` tokens
2. **Expression basic:** `"\${x}"` -> `EXPR_START`, `EXPR_CONTENT`, `EXPR_END`
3. **Expression with filter (PARS-01 + filter disambiguation):** `"\${x | h,trim}"` -> `EXPR_START`, `EXPR_CONTENT`, `FILTER_SEP`, `EXPR_CONTENT`/`FILTER_NAME` (depending on how filter names are tokenized), `EXPR_END`. The key assertion: the `|` produces `FILTER_SEP`, not `EXPR_CONTENT`.
4. **Nested braces (PARS-02):** `"\${{'key': 'val'}}"` -> `EXPR_START`, `EXPR_CONTENT` (covering `{'key': 'val'}`), `EXPR_END`. The inner `}` must NOT produce `EXPR_END`.
5. **Control line:** `"% for i in items:"` (at line start) -> `CONTROL_LINE`
6. **Escaped percent:** `"%% not a control line"` (at line start) -> `TEMPLATE_TEXT`
7. **Line comment:** `"## this is a comment"` -> `LINE_COMMENT`
8. **Doc comment:** `"<%doc>comment body</%doc>"` -> `DOC_OPEN`, `DOC_CONTENT`, `DOC_CLOSE`
9. **Named tag:** `"<%def name=\"foo\">"` -> `TAG_OPEN`, `WHITE_SPACE`, `TAG_ATTR_NAME`, `TAG_ATTR_EQ`, `TAG_ATTR_VALUE`, `TAG_CLOSE` (approximate — exact split depends on JFlex rule matching)
10. **End tag:** `"</%def>"` -> `END_TAG`
11. **Code block:** `"<% x = 1 %>"` -> `CODE_OPEN`, `CODE_CONTENT`, `CODE_CLOSE`
12. **Module block:** `"<%! import os %>"` -> `MODULE_OPEN`, `MODULE_CONTENT`, `CODE_CLOSE`
13. **Boolean OR vs filter:** `"\${a || b}"` -> `EXPR_START`, `EXPR_CONTENT` (containing `a || b`), `EXPR_END`. The `||` must NOT produce `FILTER_SEP`.
14. **Restart semantics (PARS-03):** Verify that after every top-level construct, the lexer state is `0` (YYINITIAL). Call `lexer.getState()` at the start of each new template text region and assert it equals `0`.

**IMPORTANT on test assertions:** Do not assert exact token text boundaries too rigidly — the JFlex lexer may split template text differently depending on rule matching. Focus on:
- Correct token TYPE sequence (the right IElementType)
- No BAD_CHARACTER tokens for valid Mako syntax
- FILTER_SEP appears for `|` inside `${...}` (not `||`)
- EXPR_END only at the correct closing `}`
- State is 0 at construct boundaries

Run `./gradlew test` to execute the tests.

If tests fail due to unexpected token splits, adjust the .flex file rules and regenerate (`./gradlew clean generateMakoLexer build test`). This is expected iteration — the flex rules from research are pseudo-code and may need tuning for JFlex syntax.
