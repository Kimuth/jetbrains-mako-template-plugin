<objective>
Fix GrammarKit parser so END_TAG is always included inside DEF_TAG/BLOCK_TAG PSI nodes regardless of tag body content.

Purpose: UAT revealed that <%def> and <%block> fold arrows depend on body content -- tags with only plain text (TEMPLATE_TEXT) lose their END_TAG to file-level orphaning, breaking fold regions and cascading to destroy subsequent sibling tags. The root cause is in the grammar: TEMPLATE_TEXT matched by bare `consumeToken(TEMPLATE_TEXT)` in the `item_()` alternatives does not update GrammarKit's ErrorState, so the subsequent `consumeToken(END_TAG)` step in `def_tag`/`block_tag` fails.

Output: Fixed Mako.bnf, regenerated parser, regression tests proving TEMPLATE_TEXT-body tags fold correctly with sibling tags intact.
</objective>

    **Root cause:** In the current grammar, `item_` has `TEMPLATE_TEXT` as a bare token alternative (line 60: `| TEMPLATE_TEXT`). When `item_*` inside `def_tag`/`block_tag` matches TEMPLATE_TEXT via plain `consumeToken(TEMPLATE_TEXT)`, GrammarKit's ErrorState is not updated (no pin, no recoverWhile on the enclosing rule). The subsequent step in `def_tag` -- `consumeToken(END_TAG)` -- then fails because the parser's internal `lastVariantAt`/`errorReportedAt` state was not advanced by the unpinned token consumption.

    **Fix strategy:** Replace the bare `TEMPLATE_TEXT` token alternative in `item_` with a named rule `template_text_content` that wraps TEMPLATE_TEXT. This creates a real BNF rule with its own marker in the generated parser, which properly updates ErrorState on consumption. The rule does NOT need a pin or recoverWhile itself -- merely being a named rule (rather than a raw consumeToken) is sufficient because GrammarKit's `enter_section_`/`exit_section_` pair updates the error recovery bookkeeping.

    **IMPORTANT: Make template_text_content a private rule** so it does NOT generate a new composite element type. Private rules in GrammarKit are inlined into the alternatives without creating new IElementType constants or PSI classes. This avoids any MakoTypes.java changes beyond the parser logic. Use:

    ```
    private template_text_content ::= TEMPLATE_TEXT
    ```
