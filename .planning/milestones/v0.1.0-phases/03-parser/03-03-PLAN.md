<objective>
Fix CONTROL_LINE token/composite name collision (GAP-01) by renaming the BNF rule from `control_line` to `control_line_stmt`, regenerating the parser, re-adding token delegates to MakoTypes.java, and updating test fixtures.

Purpose: The BNF rule `control_line` generates a composite element type `CONTROL_LINE` in MakoTypes.java that shadows the lexer token delegate of the same name. The parser's `consumeToken(builder_, CONTROL_LINE)` resolves to the composite MakoElementType instance (via `static import MakoTypes.*`), but the lexer emits a different IElementType instance from MakoTokenTypes.CONTROL_LINE. Since they are different objects, token matching fails silently -- CONTROL_LINE tokens produce PsiErrorElements instead of typed MakoControlLineImpl nodes. The same collision breaks recovery predicates (tag_recover, expression_recover) which reference CONTROL_LINE to detect construct boundaries.

Output: Corrected parser where CONTROL_LINE tokens produce MakoControlLineStmtImpl(CONTROL_LINE_STMT) PSI nodes, recovery predicates properly stop at control line boundaries, and all tests pass.
</objective>
