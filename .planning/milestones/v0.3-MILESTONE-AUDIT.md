## Unsatisfied Requirements Detail

### HINJ-05: CSS completion inside `<style>` tags

**Description:** CSS completion and validation active inside `<style>` tags in `.mako` files

**Phase:** 18/20

**Evidence of non-completion:**
- Phase 20-03 human IDE: `color:` + Ctrl+Space produces no CSS suggestions; plain-text word completion only
- Root cause documented: `MultiHostInjector`/`LanguageInjectionContributor` for CSSLanguage inside `<style>` elements not registered
- `MakoEditorHighlighterProvider` wires HTML _coloring_ in TEMPLATE_TEXT via `LayeredLexerEditorHighlighter`, but that does not activate CSS sub-language injection inside `<style>` element ranges

**Why not a Phase 20 blocker per Phase 20's own verification:**
Phase 20 success criterion #4 was interpreted as having an or-clause ("active OR gap explicitly documented"). The verifier accepted the gap documentation as satisfying the phase goal. However at the **milestone level**, the feature requirement itself (CSS completion) is not met.

**Path to resolution:** Implement `MultiHostInjector` or `LanguageInjectionContributor` EP to inject `CSSLanguage` into `<style>` element content ranges within the HTML PSI tree of `.mako` files.

---

### HINJ-06: JavaScript completion inside `<script>` tags

**Description:** JavaScript completion and validation active inside `<script>` tags in `.mako` files

**Phase:** 18/20

**Evidence of non-completion:**
- Phase 20-03 human IDE: `document.getElementById` etc. completions not active; same symptom as HINJ-05
- Same root cause as HINJ-05 — `MultiHostInjector`/`LanguageInjectionContributor` for JavaScriptLanguage not registered

**Path to resolution:** Same pattern as HINJ-05 but targeting `JavaScriptLanguage` within `<script>` element content ranges.
