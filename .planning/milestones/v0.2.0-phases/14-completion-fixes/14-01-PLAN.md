<task type="auto">
  <name>Task 1: Fix <%doc insert handler replacement range (COMP-01)</name>
  <files>src/main/kotlin/com/schtilig/mako/lang/completion/MakoCompletionContributor.kt</files>
  <action>
In `TagNameCompletionProvider.addCompletions`, the `<%doc` branch inside the `for (tagName in TAG_NAMES)` loop has an insert handler that computes the replacement start position as `ctx.startOffset - 2`. This is wrong when partial text has been typed (e.g., `<%d`), because `ctx.startOffset` varies based on what the platform considers the "start" of the completion item, not where `<%` is.

`ltPos` is already computed correctly a few lines above the loop (`val ltPos = textBefore.lastIndexOf("<%")`). Capture `ltPos` in the lambda by using it directly — Kotlin lambdas close over val locals automatically.

Replace both occurrences of `ctx.startOffset - 2` inside the `<%doc` handler with `ltPos`:

Current (lines ~134 and ~137):
```kotlin
ctx.document.replaceString(ctx.startOffset - 2, ctx.tailOffset, docSnippet)
ctx.commitDocument()
val innerOffset = ctx.startOffset - 2 + "<%doc>\n".length
```

Change to:
```kotlin
ctx.document.replaceString(ltPos, ctx.tailOffset, docSnippet)
ctx.commitDocument()
val innerOffset = ltPos + "<%doc>\n".length
```

No other changes to the `<%doc` handler. The other tag handlers already use `ctx.startOffset - 2` on line ~146; those have the same latent bug but are not in scope for COMP-01 (COMP-01 specifically calls out the `<%doc` handler). Leave the non-doc handlers unchanged to minimize diff scope.
  </action>
  <verify>./gradlew test --tests MakoCompletionTest</verify>
  <done>All MakoCompletionTest tests pass. The <%doc insert handler uses ltPos not ctx.startOffset - 2.</done>
</task>

<task type="auto">
  <name>Task 2: Eliminate full-file text allocation in tag-name provider (COMP-02)</name>
  <files>src/main/kotlin/com/schtilig/mako/lang/completion/MakoCompletionContributor.kt</files>
  <action>
In `TagNameCompletionProvider.addCompletions`, line:
```kotlin
val textBefore = file.text.substring(0, offset)
```
…allocates a new `String` of up to the full file length on every keystroke. Replace it with a backward scan over `parameters.editor.document.charsSequence` (a `CharSequence` view backed by the document buffer — no allocation).

Remove the `file` variable reference entirely from this path (the `file` val is still used for the language guard check, so keep that line). Replace the two-step `file.text.substring` + `lastIndexOf("<%")` with a manual backward scan:

```kotlin
val chars = parameters.editor.document.charsSequence
// Find ltPos by scanning backward from offset for "<%"
var ltPos = -1
var i = offset - 1
while (i > 0) {
    if (chars[i] == '%' && chars[i - 1] == '<') {
        ltPos = i - 1
        break
    }
    i--
}
if (ltPos < 0) return
val partial = chars.subSequence(ltPos + 2, offset).toString()
```

Then remove the now-unused `val textBefore = ...` and `val ltPos = textBefore.lastIndexOf(...)` lines. The `val partial` that was derived from `textBefore` is replaced by the `chars.subSequence` call above.

The `file` val on the first line of the method (`val file = parameters.originalFile`) is still needed for the language guard check (`file.language.id != "Mako Template"`), so keep it. Only the `textBefore`/`ltPos` derivation changes.

After this change `ltPos` is an `Int` pointing directly at the `<` of `<%`, which is what Task 1 also requires. Both tasks modify the same method; apply Task 1's changes first (using `ltPos` in the insert handler), then apply Task 2's changes to recompute `ltPos` via `charsSequence`.

Ensure the early-return guard `if (offset < 2) return` is preserved or moved to before the backward scan loop to avoid an index-out-of-bounds when `offset < 2`.
  </action>
