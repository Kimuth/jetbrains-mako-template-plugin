Fix MakoFoldingBuilder so that doc comments, code blocks, and module blocks nested inside <%def> or <%block> tags produce fold regions, and replace the brittle string-based DUMMY_BLOCK detection with a language identity check.

Purpose: The three fold-building helpers currently walk only direct children of root, so any fold construct inside a def or block body is silently skipped. The DUMMY_BLOCK check compares class name strings, which breaks when JetBrains renames internal types.

Output: Updated MakoFoldingBuilder.kt with recursive helpers and a language-based DUMMY_BLOCK guard. New tests asserting nested folds appear and the language check works.
</objective>

  <action>
Replace the three sibling-scanning helpers with a shared recursive ASTNode walker so nested constructs inside <%def> or <%block> are discovered.

Current problem: each helper starts from `root.node.firstChildNode` and walks `node.treeNext` — only direct children of root are visited, so a <%doc> inside a <%def> is invisible to the fold builder.

Add a private helper to MakoFoldingBuilder:

```kotlin
private fun walkAllNodes(node: ASTNode?, visitor: (ASTNode) -> Unit) {
    var current = node
    while (current != null) {
        visitor(current)
        walkAllNodes(current.firstChildNode, visitor)
        current = current.treeNext
    }
}
```

Then rewrite each of the three helpers to call `walkAllNodes(root.node.firstChildNode) { node -> ... }` instead of the flat loop. The visitor body is the same logic as before — only the loop mechanism changes.

Example rewrite for buildDocCommentFolds:
```kotlin
private fun buildDocCommentFolds(root: PsiElement, descriptors: MutableList<FoldingDescriptor>) {
    walkAllNodes(root.node.firstChildNode) { node ->
        if (node.elementType == MakoTokenTypes.DOC_OPEN) {
            var sibling = node.treeNext
            while (sibling != null && sibling.elementType != MakoTokenTypes.DOC_CLOSE) {
                sibling = sibling.treeNext
            }
            if (sibling != null) {
                val range = TextRange(node.startOffset, sibling.startOffset + sibling.textLength)
                descriptors.add(
                    FoldingDescriptor(node, range, null, Collections.emptySet(), false, "<%doc>...</%doc>", true)
                )
            }
        }
    }
}
```

Apply the same pattern to buildModuleBlockFolds (checking MODULE_BLOCK composite and MODULE_OPEN raw token) and buildCodeBlockFolds (checking CODE_BLOCK composite and CODE_OPEN raw token). For composite nodes (MODULE_BLOCK, CODE_BLOCK), use findClosingTokenEnd as before. For raw open tokens, scan treeNext siblings at the same level.

Do NOT change buildFoldRegions, buildControlFlowFoldsUnder, collectControlLineNodes, or findClosingTokenEnd in this task.
