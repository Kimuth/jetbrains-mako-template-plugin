### Human Verification Required

The following items cannot be verified programmatically and require manual testing in PyCharm:

#### 1. Live Syntax Highlighting

**Test:** Open a `.mako` file in PyCharm with the plugin installed (run `./gradlew runIde`). Type a file with mixed Mako constructs: `${name}`, `## comment`, `% for i in x:`, `<%def name="foo">`.
**Expected:** Each token type receives distinct (or at least non-default) coloring. No gray/uncolored regions. No "unknown file type" fallback.
**Why human:** Syntax highlighting requires the SyntaxHighlighter (Phase 4) which is not yet implemented. This test confirms the lexer pipeline is invoked without exceptions, but full coloring is a Phase 4 deliverable.

#### 2. Mid-File Edit Does Not Corrupt Coloring

**Test:** Open a large `.mako` file (500+ lines). Edit a `${...}` expression on line 10. Observe token coloring on lines 100-200.
**Expected:** Token coloring below line 10 remains correct and does not shift or corrupt.
**Why human:** Incremental re-lex behavior requires observing IDE editor response in real time. The test suite verifies state=0 at boundaries, but the incremental re-lex integration with the IntelliJ highlighting daemon can only be confirmed visually.

#### 3. No Exceptions on .mako File Open

**Test:** Run `./gradlew runIde`, open PyCharm, open any `.mako` file.
**Expected:** File opens without exceptions in the IDE log. No "MakoParser not yet implemented" UnsupportedOperationException surfaces as an error dialog (it is only thrown when PSI parsing is triggered, not on file open for lexer-only use).
**Why human:** Runtime exception behavior during IDE startup and file open requires manual observation of the IDE log.
