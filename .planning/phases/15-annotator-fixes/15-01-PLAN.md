Both files currently guard against non-Mako files using a string literal: `language.id != "Mako Template"`. This must be replaced with an identity comparison against the singleton `MakoLanguage.INSTANCE` (which in Kotlin is accessed as `MakoLanguage` since it is a Kotlin `object`).

**MakoAnnotator.kt** — line 20:

Current:
```kotlin
if (element.containingFile.language.id != "Mako Template") return
```

Change to:
```kotlin
if (element.containingFile.language != MakoLanguage) return
```

Add the import at the top of the file (after the existing imports):
```kotlin
import com.schtilig.mako.MakoLanguage
```

**MakoCompletionContributor.kt** — the guard is inside `TagNameCompletionProvider.addCompletions`, currently:
```kotlin
if (file.language.id != "Mako Template") return
```

Change to:
```kotlin
if (file.language != MakoLanguage) return
```

Add the import at the top of the file (after the existing imports, in alphabetical order with other `com.schtilig.mako` imports):
```kotlin
import com.schtilig.mako.MakoLanguage
```

No other changes to either file. The `MakoLanguage` Kotlin object is a singleton; `language != MakoLanguage` is an identity (reference) comparison in Kotlin, equivalent to `language !== MakoLanguage.INSTANCE` in Java. This is the correct pattern for JetBrains plugin language guards.
