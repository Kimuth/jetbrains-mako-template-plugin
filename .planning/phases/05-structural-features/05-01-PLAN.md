<objective>
Implement code folding for all Mako block constructs so users can collapse template sections via gutter fold arrows.

Purpose: Users working with large Mako templates need to collapse `<%def>`, `<%block>`, control flow (`% for`, `% if`, `% while`), `<%doc>`, and `<%!>` blocks to reduce visual clutter. Doc comments and module blocks should collapse by default on file open.

Output: `MakoFoldingBuilder.kt` registered in `plugin.xml`, plus a folding test with test data fixture.
</objective>

  <action>
Create new package `lang/folding/` and file `MakoFoldingBuilder.kt`.

The class extends `FoldingBuilderEx()` and implements `DumbAware` (CRITICAL: without DumbAware, folding tests fail because the test framework runs in dumb mode).

In `buildFoldRegions(root: PsiElement, document: Document, quick: Boolean)`:

1. **def_tag folding:** Use `PsiTreeUtil.collectElementsOfType(root, MakoDefTag::class.java)` and create `FoldingDescriptor(def.node, def.textRange)` for each. These start expanded (default).

2. **block_tag folding:** Same pattern with `MakoBlockTag::class.java`. Start expanded.

3. **doc_comment folding:** Use `MakoDocComment::class.java`. Create `FoldingDescriptor` with `collapsedByDefault=true` directly in the constructor. Use the 7-arg constructor: `FoldingDescriptor(node, textRange, group=null, dependencies=Collections.emptySet(), neverExpands=false, placeholderText="<%doc>...</%doc>", collapsedByDefault=true)`. Do NOT rely on `isCollapsedByDefault()` for these — use the descriptor constructor.

4. **module_block folding:** Use `MakoModuleBlock::class.java`. Same pattern as doc_comment with `collapsedByDefault=true` and placeholder `"<%!...%>"`.

5. **Control flow folding (sibling-scan algorithm):**
   - Define `OPENING_KEYWORDS = setOf("for", "if", "while")` and `CLOSING_KEYWORDS = setOf("endfor", "endif", "endwhile")` as companion constants.
   - Create `extractKeyword(text: String): String` that strips leading whitespace, removes `%`, strips whitespace again, and returns the first word. Example: `"  % for item in items:"` -> `"for"`.
   - Create `buildControlFlowFoldsUnder(parent: PsiElement): List<FoldingDescriptor>` that iterates direct children of `parent` via `parent.firstChild` / `child.nextSibling`. For each `MakoControlLineStmt`, extract keyword. If opening keyword, push onto `ArrayDeque<MakoControlLineStmt>` stack. If closing keyword AND stack is not empty (guard against underflow for malformed files), pop the matching open and create `FoldingDescriptor(openLine.node, TextRange(openLine.textRange.startOffset, child.textRange.endOffset))`.
   - Call `buildControlFlowFoldsUnder` for: the root file element itself (if `root is MakoFile`), and for every `MakoDefTag` and `MakoBlockTag` found via `PsiTreeUtil.collectElementsOfType` (so control flow nested inside defs/blocks is also folded).
   - IMPORTANT: Only scan direct children in `buildControlFlowFoldsUnder` — do NOT recurse into nested def/block tags from within the function. The separate `PsiTreeUtil.collectElementsOfType` calls handle visiting def/block bodies.

`getPlaceholderText(node: ASTNode)`: Return `"..."` as the generic fallback. Doc comment and module block placeholders are set directly in their FoldingDescriptor constructors.

`isCollapsedByDefault(node: ASTNode)`: Return `false`. Doc comment and module block use per-descriptor `collapsedByDefault=true` in the constructor, so this method only needs the default false return.

Register in `plugin.xml` inside the `<extensions>` block, after the Phase 4 commenter registration:
```xml
<!-- Phase 5: Code Folding -->
<lang.foldingBuilder language="Mako Template"
    implementationClass="com.github.kimuth.jetbrainsmakotemplateplugin.lang.folding.MakoFoldingBuilder"/>
```

Language ID MUST be exactly `"Mako Template"` — copy from existing registrations to avoid typos.

```
<fold text='<%doc>...</%doc>'><%doc>
This documentation should be collapsed by default.
</%doc></fold>

<fold text='<%!...%>'><%!
    import os
%></fold>

<fold text='...'><%def name="greet">
Hello ${name}!
</%def></fold>

<fold text='...'><%block name="header">
<h1>Title</h1>
</%block></fold>

<fold text='...'>% for item in items:
    ${item}
% endfor</fold>

<fold text='...'>% if show:
    <p>Visible</p>
% endif</fold>

<fold text='...'>% while count > 0:
    <p>Counting</p>
% endwhile</fold>
```

IMPORTANT: The `<fold text='...'>` tag wraps the ENTIRE fold region text. The `text` attribute must exactly match what `getPlaceholderText()` returns for that node type. For def_tag, block_tag, and control flow nodes, this is `"..."` (the generic fallback). For doc_comment and module_block, the placeholder is set in the FoldingDescriptor constructor as `"<%doc>...</%doc>"` and `"<%!...%>"` respectively.

NOTE: The `<fold>` tag for doc_comment and module_block must start BEFORE the opening delimiter because the fold region is the entire node textRange. Similarly for control flow, the fold starts at the `% for` line and ends at the `% endfor` line (inclusive).
