<objective>
Implement the Structure View panel so users can see all `<%def>` and `<%block>` declarations as a navigable tree in View > Tool Windows > Structure (or Ctrl+F12).

Purpose: Users working with complex Mako templates with many named defs and blocks need a quick overview and navigation mechanism. Clicking a node in the Structure view jumps the editor caret to that declaration.

Output: Three-class Structure View stack (`MakoStructureViewFactory`, `MakoStructureViewModel`, `MakoStructureViewElement`) registered in `plugin.xml`, plus a structure view test.
</objective>

  <action>
Create new package `lang/structure/` with three files:

**MakoStructureViewFactory.kt:**
Implements `PsiStructureViewFactory`. The `getStructureViewBuilder(psiFile: PsiFile)` method returns an anonymous `TreeBasedStructureViewBuilder` whose `createStructureViewModel(editor: Editor?)` creates a `MakoStructureViewModel(editor, psiFile)`.

**MakoStructureViewModel.kt:**
Extends `StructureViewModelBase(psiFile, editor, MakoStructureViewElement(psiFile as NavigatablePsiElement))` and implements `StructureViewModel.ElementInfoProvider`.

- `getSuitableClasses()`: Return `arrayOf(MakoDefTag::class.java, MakoBlockTag::class.java)`. These MUST match the types returned by `MakoStructureViewElement.getChildren()` — this is required for the autoscroll-from-source feature to work.
- `isAlwaysShowsPlus(element)`: Return `false`.
- `isAlwaysLeaf(element)`: Return `false` (defs can contain nested defs/blocks, so they are not always leaves).

Note: `MakoFile` extends `PsiFileBase` which extends `PsiFile` which implements `NavigatablePsiElement`, so the cast `psiFile as NavigatablePsiElement` is safe.

**MakoStructureViewElement.kt:**
Implements `StructureViewTreeElement` and `SortableTreeElement`. Constructor takes `NavigatablePsiElement`.

- `getValue()`: Return `element`.
- `navigate(requestFocus)`: Delegate to `element.navigate(requestFocus)`. Navigation is free because `MakoDefTagMixin` and `MakoBlockTagMixin` extend `ASTWrapperPsiElement` which implements `NavigatablePsiElement`.
- `canNavigate()`: Delegate to `element.canNavigate()`.
- `canNavigateToSource()`: Delegate to `element.canNavigateToSource()`.
- `getAlphaSortKey()`: Return `element.name ?: ""`.
- `getPresentation()`: Return `element.presentation ?: PresentationData(element.name ?: "<unnamed>", null, MakoIcons.FILE, null)`. Use `MakoIcons.FILE` as the icon for all nodes.
- `getChildren()`:
  - When `element is MakoFile`: collect direct `MakoDefTag` and `MakoBlockTag` children using `PsiTreeUtil.getChildrenOfTypeAsList()`, cast each to `NavigatablePsiElement`, wrap in `MakoStructureViewElement`.
  - When `element is MakoDefTag`: same — collect nested `MakoDefTag` and `MakoBlockTag` children (supports nested defs).
  - When `element is MakoBlockTag`: same — collect nested `MakoDefTag` and `MakoBlockTag` children.
  - Otherwise: return `TreeElement.EMPTY_ARRAY`.

Register in `plugin.xml` inside the `<extensions>` block, after the Phase 5 folding builder registration:
```xml
<!-- Phase 5: Structure View -->
<lang.psiStructureViewFactory language="Mako Template"
    implementationClass="com.github.kimuth.jetbrainsmakotemplateplugin.lang.structure.MakoStructureViewFactory"/>
```

Language ID MUST be exactly `"Mako Template"`.

Create `src/test/kotlin/com/github/kimuth/jetbrainsmakotemplateplugin/lang/MakoStructureViewTest.kt` that verifies the Structure View shows the correct tree of def and block nodes.

The test class extends `BasePlatformTestCase`.

**Test method `testStructureView()`:**

1. Use `myFixture.configureByText("test.mako", content)` with Mako content that includes:
   - A top-level `<%def name="greet">...</%def>`
   - A top-level `<%block name="header">...</%block>`
   - A nested `<%def name="inner">...</%def>` inside the first def
   - Some template text and control flow outside defs (should NOT appear in structure)

2. Get the structure view model:
```kotlin
val builder = StructureViewBuilder.PROVIDER.getStructureViewBuilder(
    myFixture.file.fileType, myFixture.editor, project
)
```

Alternative approach using the factory directly:
```kotlin
val factory = LanguageStructureViewBuilder.INSTANCE.forLanguage(MakoLanguage)
```

Or the simplest test approach — directly instantiate and test the model:
```kotlin
val model = MakoStructureViewModel(myFixture.editor, myFixture.file)
val root = model.root
```

3. Assert root element's children:
   - Root should have children (the top-level def and block nodes)
   - Find the child whose presentation text is "greet" (the def)
   - Find the child whose presentation text is "header" (the block)
   - Assert there are exactly 2 top-level children

4. Assert nested children:
   - The "greet" def node should have 1 child (the nested "inner" def)
   - The "header" block should have 0 children

5. Assert suitable classes:
   - `model.suitableClasses` should contain `MakoDefTag::class.java` and `MakoBlockTag::class.java`

After creating the test, run `./gradlew build` to verify it passes along with all existing tests.

NOTE: If direct model instantiation causes issues in the test framework, use `myFixture.testStructureView { svm -> ... }` which is the standard IntelliJ Platform test approach for structure views. This callback receives a `StructureViewComponent` from which you can access the tree model.
