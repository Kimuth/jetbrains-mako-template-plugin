The `FILTER_NAME` constant in `MakoTokenTypes.kt`, the corresponding `when`-branch in `MakoSyntaxHighlighter.kt`, and the static delegate in `MakoTypes.java` are therefore unreachable dead code.

    Three targeted deletions:

    1. In `src/main/kotlin/com/schtilig/mako/lang/MakoTokenTypes.kt`: Delete line 12 entirely:
       ```
       @JvmField val FILTER_NAME    = IElementType("FILTER_NAME",    MakoLanguage) // h, trim, u, x, n
       ```
       Leave `FILTER_SEP` (line 11) untouched — the lexer does emit that token.

    2. In `src/main/kotlin/com/schtilig/mako/lang/highlighting/MakoSyntaxHighlighter.kt`: Delete line 93 entirely:
       ```
           MakoTokenTypes.FILTER_NAME  -> EXPRESSION_KEYS
       ```
       The preceding `FILTER_SEP -> EXPRESSION_KEYS` branch (line 92) remains — that token is live.

    3. In `src/main/gen/com/schtilig/mako/lang/psi/MakoTypes.java`: Delete line 45 entirely:
       ```
         IElementType FILTER_NAME    = MakoTokenTypes.FILTER_NAME;
       ```
       Note: This is a generated file but the comment at the top of the file says "not intended for manual editing" — however, the instructions in CLAUDE.md and ROADMAP acknowledge that MakoTypes.java must be kept in sync manually when token constants change, since GrammarKit regeneration is IDE-only. Edit it directly. Leave all other delegate fields untouched.

    Do NOT remove `FILTER_SEP` — it is emitted by the lexer and used by the Python injector (Phase 11-02 fix) to determine injection boundaries.
  </action>
